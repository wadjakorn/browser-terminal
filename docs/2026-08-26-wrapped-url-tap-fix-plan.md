# แตะ URL ที่ถูกตัดหลายบรรทัดใน Claude Code — สาเหตุและแผนแก้

สถานะ: **ทำแล้ว** (branch `wrapped-url-tap`) · ไฟล์ที่เกี่ยวข้อง: `web/links.ts`, `web/links.test.ts`

## อาการ

แตะ URL ในเทอร์มินัลบนมือถือ:

- URL ที่อยู่ครบในบรรทัดเดียว → เปิดถูกต้อง
- URL ที่ Claude Code ตัดข้ามบรรทัด → ได้เฉพาะ **ท่อนแรก** เท่านั้น (ลิงก์เสีย)

## หลักฐานจากของจริง

อ่านบัฟเฟอร์เพนที่ Claude Code รันอยู่จริงตอนนี้ (`herdr pane read w74:p1 --source recent`)
เพนกว้าง **79** คอลัมน์:

```
  http://wadjakorn-bmax:8080/browser-console/docs/2026-08-26-wrapped-url-tap-fi   ← 79 คอลัมน์เต็มพอดี
  x-plan.md                                                                       ← ย่อหน้า 2 ช่อง
```

ข้อเท็จจริงสองข้อจากตัวอย่างนี้:

1. Claude Code **เขียนเต็มถึงคอลัมน์สุดท้าย** ตอนตัดบรรทัด (79/79) — ไม่ได้เว้นรางขวา
2. บรรทัดต่อเนื่องมี **ย่อหน้า 2 ช่อง** นำหน้า

เทียบกับ bash ที่หัก hard wrap เอง (เพนกว้าง 69) — เต็มขอบเหมือนกันแต่ **ไม่มีย่อหน้า**:

```
see https://example.com/very/long/path/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
```

ความต่างข้อเดียวคือ **ย่อหน้า** และนั่นคือทั้งหมดของบั๊ก

ตรวจแล้วว่า Claude Code **ไม่ได้ยิง OSC 8 hyperlink** (`grep -c $'\e]8'` บนสตรีม ansi ได้ 0)
การอ่าน URI จากเซลล์แทนการ parse ข้อความจึงไม่ใช่ทางเลือกที่มีอยู่ — ต้อง parse เอง

## สาเหตุ (root cause) — สองข้อ

### 1. ต่อบรรทัดแล้วย่อหน้าเข้าไปคั่นกลาง URL (สาเหตุของอาการที่รายงาน)

`overflowsToNextRow()` คืน true ถูกต้องอยู่แล้ว (แถวยาวเท่าความกว้างเพนและไม่จบด้วย
ช่องว่าง) การต่อบรรทัด **เกิดขึ้นจริง** ปัญหาอยู่ที่ขั้นต่อสตริง:

```ts
for (let l = first; l <= last; l++) joined += rowText(l).padEnd(width, ' ');
```

ต่อแถวดิบ ⇒ `…-tap-fi` + `␣␣x-plan.md` ⇒ มีช่องว่างคั่นกลาง URL ⇒ regex
(`[^\s…]*`) ตัดตรงนั้นพอดี ⇒ คืนเฉพาะท่อนแรก **ตรงกับอาการที่รายงานเป๊ะ**

bash รอดเพราะบรรทัดต่อเนื่องเริ่มที่คอลัมน์ 0 ไม่มีอะไรมาคั่น

### 2. นับ "ความยาวสตริง" แทน "จำนวนคอลัมน์"

ทั้ง `overflowsToNextRow()` และการคำนวณ offset ใช้ `text.length` เทียบกับจำนวนคอลัมน์
แต่ `readLine()` มาจาก `translateToString()` ซึ่ง **หนึ่งอักขระ JS ไม่เท่ากับหนึ่งคอลัมน์**:

- อักษรกว้าง (CJK, emoji เช่น `⎿` `●` ที่ Claude Code ใช้) กิน 2 คอลัมน์แต่ได้ 1 อักขระ
  เซลล์ครึ่งขวาคืน `''` → `text.length < width` → **ไม่ต่อบรรทัด**
- สระ/วรรณยุกต์ไทยอยู่เซลล์เดียวกับพยัญชนะแต่เป็นอักขระแยก → `text.length > width`
  → **ไม่ต่อบรรทัด** เช่นกัน (เทอร์มินัลนี้มีข้อความไทยเป็นปกติ)

ผลคือแถวไหนมีอักษรกว้างหรือสระไทยปนอยู่ การต่อบรรทัดจะเงียบไปเฉยๆ และ offset ของ
เซลล์ที่แตะก็เลื่อนผิดตำแหน่งด้วย ข้อนี้ต้องแก้พร้อมกัน ไม่งั้นแก้ข้อ 1 แล้วยังพังเป็นครั้งคราว
แบบหาสาเหตุไม่เจอ

## ทางแก้

ทำทุกอย่างเป็น **คอลัมน์** ไม่ใช่ตัวอักษร โดยอ่านผ่าน `readCell()` ทีละเซลล์
(`readLine()` ไม่ถูกใช้อีกต่อไป — ถอดออกจาก `LinkTerminalPort` ได้เลย)

1. **sanitize** — อักษรวาดกล่อง (`BORDER_CHARS` จาก `pane-detect.ts`) นับเป็นช่องว่าง
   ทั้งตอนหาขอบและตอนต่อสตริง กัน `│` หลุดเข้าไปใน URL (regex ปัจจุบันไม่ได้กันไว้)
2. **เกณฑ์ล้นบรรทัด** — คอลัมน์สุดท้ายที่ไม่ว่าง (หลัง sanitize) เท่ากับ `pane.end`
   แทนการเทียบ `text.length === width`
3. **ตัด gutter** — แถวที่สองเป็นต้นไป ตัดช่องว่างนำหน้าทิ้งก่อนต่อ (URL ไม่มีช่องว่าง
   อยู่ในตัว จึงไม่มีทางตัดเนื้อ URL ทิ้ง) แถวแรกคงไว้ทั้งแถว
4. **segment list** — เก็บ `{ line, startColumn, offset, columns[] }` ต่อแถว
   แล้ว map เซลล์ที่แตะ → offset ผ่านตารางคอลัมน์ ไม่ใช่เลขคณิตความยาวสตริง
   ครึ่งขวาของอักษรกว้าง map ไปยัง offset เดียวกับครึ่งซ้าย
   คืน `null` เมื่อคอลัมน์ตกอยู่ใน gutter

ทิศทางการขยายบน/ล่างคงเดิม ไม่ต้องมีค่า slack หรือเกณฑ์ "ใกล้ขอบ" ใดๆ

ต้นทุน: อ่านเซลล์เพิ่มไม่กี่สิบถึงร้อยเซลล์ต่อการแตะหนึ่งครั้ง เทียบกับ `paneAt()` ที่
สแกน rows x columns (~8,000 เซลล์) อยู่แล้วในการแตะเดียวกัน — ไม่มีนัยสำคัญ

## ข้อจำกัดที่ตั้งใจไม่แก้รอบนี้

**scrollback ที่ถูกตัดตอนเพนกว้างกว่า/แคบกว่าปัจจุบัน** — Claude Code ไม่ re-wrap
ข้อความเก่าเมื่อเพนถูกย่อขยาย (มือถือเจอบ่อยเพราะคีย์บอร์ดเด้งและการหมุนจอ)
หลักฐาน: เพน `w79:p1` กว้าง 79 ตอนนี้ แต่บล็อกเก่าจบที่คอลัมน์ 68 แล้วขึ้นบรรทัดใหม่

เคสนี้ `overflowsToNextRow()` คืน false → ไม่ต่อบรรทัด → ยังได้ URL ท่อนแรกเหมือนเดิม
**ไม่แย่ลงกว่าวันนี้** การจะแก้ต้องใช้เกณฑ์ "ใกล้ขอบแบบมี slack" ซึ่งเปิดทางให้ต่อผิด
และไม่มีตัวเลขที่คาลิเบรตได้จากหลักฐานที่มี — แยกเป็นงานถัดไปเมื่อเจอว่ากวนใจจริง

## เทสที่ต้องเพิ่ม (`web/links.test.ts`)

`fakePort` เดิม pad ทุกแถวเต็ม 20 อยู่แล้ว ใช้ต่อได้

1. **เคส Claude Code จริง (แดงก่อน)** — ย่อหน้า 2 ช่องและเต็มขอบ:
   แถว = `'  ' + URL.slice(0,18)`, `'  ' + URL.slice(18,36)`, … → แตะแถวไหนก็ได้ URL เต็ม
2. **regression: hard wrap เดิม** — เต็มขอบ ไม่มีย่อหน้า ต้องยังผ่าน
3. **ไม่ต่อบรรทัดที่ไม่ควรต่อ** — `['see https://a.io/x', 'and more text']`
   (แถวแรกไม่เต็มขอบ) → ได้ `https://a.io/x`
4. **อักษรกว้าง/สระไทยในแถวเดียวกับ URL** — แถวเต็มขอบที่มี `●` หรือข้อความไทยปน
   ต้องยังต่อบรรทัดได้ (เทสนี้ล้มด้วยโค้ดปัจจุบันแน่นอน ต้องใช้ `fakePort` ที่จำลอง
   เซลล์อักษรกว้างคืน `''` ในครึ่งขวา)
5. **URL ในกรอบกล่อง `│ … │`** — ไม่ต่อบรรทัด และต้องไม่ลาก `│` ติดมาใน URL
   (รอบนี้เอาแค่ "ไม่พังแบบเงียบ" ยังไม่รองรับการต่อข้ามกรอบ)
6. **แตะโดน gutter เอง** → คืน `null` ไม่ throw
7. **ยังไม่ลาก sidebar/เส้นแบ่งเข้ามา** — เทสเดิมต้องผ่านต่อ
