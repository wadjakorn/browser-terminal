# browser-terminal

เว็บเทอร์มินัลสำหรับเข้าถึง shell ของเครื่องคุณจากมือถือ — ออกแบบมาเพื่อจอเล็กและนิ้วมือ
โดยเฉพาะ มีแถวปุ่ม `Esc`/`Ctrl`/`Alt`/ลูกศร ที่คีย์บอร์ด Android ไม่มี และรองรับท่าทาง
touch ครบ (เลื่อน สะบัดให้ไหลต่อ บีบซูม กดค้างแล้วลาก)

นี่คือสิ่งที่แยกโปรเจกต์นี้ออกจาก `ttyd` และ `gotty` — ตัวอื่นเสิร์ฟ xterm.js เฉยๆ
แล้วปล่อยให้คุณสู้กับคีย์บอร์ดบนจอเอาเอง

---

## ⚠️ อ่านก่อนติดตั้ง

**แอปนี้คือการรันโค้ดอะไรก็ได้จากระยะไกล โดยเจตนา** ใครก็ตามที่ผ่านหน้า login ไปได้
จะได้ shell ที่มีสิทธิ์เท่ากับผู้ใช้ที่รัน service — อ่านไฟล์ทุกไฟล์ที่คนนั้นอ่านได้
ใช้ SSH key ที่มีอยู่ ต่อไปยังเครื่องอื่นในเครือข่ายได้

- **รหัสผ่านคือกำแพงทั้งหมด** ถ้าไม่มีการยืนยันตัวตนชั้นเครือข่ายมารองรับ
- **"แค่ LAN ในบ้าน" ไม่ใช่ขอบเขตที่ไว้ใจได้** — อุปกรณ์ IoT ที่ถูกเจาะ แขกที่ต่อ WiFi
  หรือเพื่อนบ้านที่เดารหัส WiFi ได้ ล้วนอยู่ในวงเดียวกับคุณ
- **อย่ารันเป็น root** ให้รันด้วยผู้ใช้ธรรมดาเสมอ

คำแนะนำ: อย่าให้รหัสผ่านของแอปนี้เป็นด่านเดียว — เอาไปวางไว้หลัง Tailscale, SSH tunnel
หรือ tunnel ที่มีการยืนยันตัวตนของผู้ให้บริการ

## เลือกวิธี deploy

| วิธี | TLS | ใครยิงหน้า login ได้ | เหมาะกับ |
|---|---|---|---|
| **SSH tunnel** | ไม่ต้อง (SSH ห่อให้) | เฉพาะคนที่มี SSH key | นักพัฒนา — ปลอดภัยที่สุด |
| **Tailscale** | ฟรีจาก Tailscale | เฉพาะเครื่องใน tailnet | มือถือส่วนตัว — สมดุลดีที่สุด |
| **Tunnel + auth ของผู้ให้บริการ** | ฟรีจากผู้ให้บริการ | เฉพาะคนที่ผ่าน auth | เข้าจากเน็ตนอก |
| **reverse proxy สาธารณะ** | Let's Encrypt | **ทั้งอินเทอร์เน็ต** | คนที่รู้ว่ากำลังทำอะไร |
| **LAN แบบ http** | ไม่มี | ทุกคนในวง + ดักอ่านได้ | ไม่แนะนำ ต้องเปิด `ALLOW_INSECURE` |

### SSH tunnel

```bash
# บนเครื่อง server
PUBLIC_ORIGIN=http://localhost:7000 pnpm start
# บนเครื่องของคุณ
ssh -L 7000:localhost:7000 user@server
```

เปิด `http://localhost:7000` — ไม่ต้องมี TLS เพราะ SSH เข้ารหัสให้แล้ว และเบราว์เซอร์
ถือว่า loopback เป็น secure context จึงยอมเก็บ cookie

### Tailscale

```bash
PUBLIC_ORIGIN=https://<เครื่อง>.<tailnet>.ts.net:8443 pnpm start
tailscale serve --bg --https=8443 7000
```

`tailscale serve` รองรับเฉพาะพอร์ต 443, 8443 และ 10000

### Docker

```bash
docker build -t browser-terminal .
docker run -d --env-file .env -p 127.0.0.1:7000:7000 browser-terminal
```

image ตั้ง `HOST=0.0.0.0` ไว้ให้แล้ว (ในคอนเทนเนอร์ bind loopback ไม่ได้) ความปลอดภัย
จึงไปอยู่ที่ `-p 127.0.0.1:...` ซึ่งเปิดให้เฉพาะ loopback ของ host — ถ้าเขียนเป็น
`-p 7000:7000` เฉยๆ จะเปิดสู่เครือข่ายทั้งวง

## ติดตั้ง

```bash
pnpm install
cp .env.example .env     # แล้วตั้ง CONSOLE_PASSWORD, SESSION_SECRET, PUBLIC_ORIGIN
pnpm build
pnpm start
```

### รหัสผ่านแบบ hash

```bash
pnpm hash-password        # พิมพ์รหัส แล้วเอาบรรทัดที่ได้ไปใส่ .env
```

`CONSOLE_PASSWORD` รับได้ทั้งรหัสดิบและ hash (`scrypt:...`) — แนะนำให้ใช้ hash เมื่อ
เปิดสู่เครือข่ายจริง สคริปต์รับรหัสทาง stdin ไม่ใช่ argument เพื่อไม่ให้ไปโผล่ใน `ps`
หรือค้างใน shell history

server จะไม่ยอม start ถ้า config อันตราย — รหัสผ่านสั้นหรือเป็นค่าตัวอย่าง,
`SESSION_SECRET` ยังไม่ได้ตั้ง, หรือเสิร์ฟผ่าน http ไปยัง host ที่ไม่ใช่ loopback

### เลือก shell (`SHELL_CMD`)

ค่าที่ตั้งไว้จะถูก spawn เป็น process แรกของ PTY โดยตรง ไม่ได้เข้า shell แล้วค่อยเรียก
ต่อ — ค่านี้ถูกตัดด้วยช่องว่างเฉยๆ ไม่ผ่าน shell ดังนั้น pipe, `&&` หรือ `$HOME`
จะไม่ถูกตีความ ถ้าต้องการแบบนั้นให้เขียนเป็น `bash -lc '...'`

เป็นค่าระดับเซิร์ฟเวอร์ ไม่ใช่ต่อ session — ทุกคนที่ต่อเข้ามาได้ shell เดียวกันหมด

| ค่า | เหมาะกับ |
| --- | --- |
| `herdr` (ค่าตั้งต้น) | ใช้ herdr เป็นหลักอยู่แล้ว — ได้ multiplexer + เลือกคำแล้วคัดลอกด้วยดับเบิลคลิก |
| `tmux new -A -s web` | อยากได้ terminal ธรรมดา — `-A` ทำให้ต่อใหม่ attach กลับ session เดิม |
| `bash` | ทดสอบชั่วคราวเท่านั้น |

**อย่าตั้งเป็น `bash` เปล่าถ้าจะใช้งานจริง** — proxy ตัวนี้ไม่ทำ persistence ให้
ปิดแท็บหรือเน็ตหลุดเมื่อไหร่ PTY ตายทันทีพร้อมงานที่ค้างอยู่ ซึ่งบนมือถือเกิดง่ายมาก
แค่สลับแอปนานพอ ทั้ง `herdr` และ `tmux new -A -s web` แก้ปัญหานี้ให้ ต่างกันแค่ว่า
อยากได้ UI ของ herdr ด้วยหรือไม่

แก้ `.env` แล้ว restart ได้เลย ไม่ต้อง `pnpm build` ใหม่ เพราะอ่านตอน runtime

### รันเป็น systemd user service

```bash
cp browser-console.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now browser-console
```

## การใช้งานบนมือถือ

| ท่า | ผล |
|---|---|
| กด `⛶` | เข้า/ออกโหมดเต็มหน้าจอ — ปุ่มจะแสดงเฉพาะเบราว์เซอร์ที่รองรับ Fullscreen API |
| แตะ 1 ครั้ง | คลิกซ้ายส่งให้ TUI — **ไม่เปิดคีย์บอร์ด** |
| แตะ 1 ครั้งบน URL | เปิดลิงก์ในแท็บใหม่ และ **ไม่ส่งคลิกต่อให้ TUI** (โฟกัส pane ไม่ย้าย) — รองรับ URL ที่ถูกตัดข้ามบรรทัด |
| แตะ 2 ครั้ง | คลิกสองครั้งส่งให้ TUI (herdr ใช้เลือกคำแล้วคัดลอก) — **ไม่เปิดคีย์บอร์ด** |
| ปุ่ม `⌨` ท้ายแถว | เปิด/ปิดคีย์บอร์ด (สว่างเมื่อเปิดอยู่) — ทางเดียวที่เปิดคีย์บอร์ดได้ |
| ปัดแถบปุ่มซ้าย/ขวา | เลื่อนดู quick keys ทั้งหมดในแถวเดียว ปุ่ม `⋯` และ `⌨` ไม่เลื่อนตาม |
| ปุ่ม `⋯` ท้ายแถว | คง quick row ไว้ที่เดิม แล้วห่อปุ่มที่ซ่อนทางขวาลงด้านล่าง พร้อมปิดคีย์บอร์ดบนจอ |
| ปุ่ม `⚙` ท้ายแถว | เปิดแผงปรับ bottom tools: ซ่อน/แสดงปุ่ม, เลื่อนลำดับ, reset ค่าเริ่มต้น |
| ปุ่ม `⧉` | เข้า/ออกโหมดเลือกข้อความ (สว่างเมื่ออยู่ในโหมด) — ดูหัวข้อถัดไป |
| ปุ่ม `⎘` | วางข้อความจากคลิปบอร์ดเข้า terminal |
| นิ้วเดียวลากขึ้น/ลง | เลื่อนเนื้อหา · สะบัดเร็วแล้วปล่อยจะไหลต่อ · แตะเพื่อหยุด |
| กดค้าง ~0.4 วิ แล้วลาก | ลากเมาส์ (เช่น ย่อ/ขยาย sidebar) — สั่นสั้นๆ ตอนเข้าโหมด |
| นิ้วเดียวลากในโหมด `⧉` | ลากกรอบเลือกข้อความ — **ไม่เลื่อนจอ** ออกจากโหมดก่อนถ้าจะเลื่อน |
| สองนิ้วบีบ/ถ่าง | ปรับขนาดฟอนต์ 8–24px (จำค่าไว้ในเครื่อง) |
| `Ctrl` / `Shift` / `Alt` | แตะหนึ่งครั้ง = ใช้กับ input ถัดไป · แตะสองครั้งภายใน 300ms = ล็อก · แตะอีกครั้ง = ปลด |
| `Shift Tab` | ปุ่มผสมในตัว ส่ง back-tab (`ESC [ Z`) สำหรับสลับโหมดใน Claude Code โดยไม่รวม modifier ที่ค้างอยู่ |
| ปุ่มลูกศร | แตะ = ขยับหนึ่งครั้ง · กดค้าง 350ms = ขยับต่อเนื่องทุก 75ms จนปล่อย · เริ่มปัดแนวนอนก่อนเวลาค้าง = เลื่อน quick row โดยไม่ส่งลูกศร |

quick row ไม่ตัดหน้าและไม่ย่อปุ่ม: ปัดแนวนอนเพื่อเข้าถึงชุดปุ่มเดียวกันทั้งหมด เมื่อกด
`⋯` ปุ่มแถวแรกจะอยู่ตำแหน่งเดิม และปุ่มที่เดิมต้องปัดไปทางขวาจึงจะเห็นจะห่อลงในพื้นที่
ด้านล่าง ไม่มีการสร้างปุ่มชุดที่สองหรือทำปุ่มซ้ำ ขณะเปิด พื้นที่ dock อยู่ใต้ terminal
และเลื่อนแนวตั้งได้เมื่อจอแนวนอนเตี้ย ปุ่ม `⋯` กับ
`⌨` อยู่กับที่เสมอ

ถ้ากด `⋯` ขณะที่คีย์บอร์ดบนจอเปิดอยู่ ตารางจะรับพื้นที่เท่ากับพื้นที่ที่คีย์บอร์ด
คืนให้ `visualViewport` ระหว่างที่มันปิด จึงไม่ทำให้ terminal กระโดดสูงขึ้นหรือต่ำลง
เมื่อกด `⋯` อีกครั้ง ระบบจะจำว่าเคยแทนคีย์บอร์ดไว้และเรียกคีย์บอร์ดกลับมาให้ทันที
โดยไม่ต้องแตะ `⌨` ซ้ำ ถ้าเปิดตารางในตอนที่ไม่มีคีย์บอร์ด ตารางจะพับโดยไม่เปิด
คีย์บอร์ดเองและใช้ความสูงตามเนื้อหาโดยจำกัดไว้ที่ครึ่งจอ ปุ่ม `⌨` ยังใช้บังคับสลับ
ระหว่างตารางกับคีย์บอร์ดได้เสมอ

```
Esc  Tab  Ctrl  ↑  ↓  ←  →  Shift Tab  Shift  Alt  ^C  ⧉  ⎘  |  ~  /  -
```

กด `⚙` เพื่อปรับ bottom tools ในเครื่องนี้ได้: ซ่อน/แสดงปุ่ม, เลื่อนลำดับปุ่ม, และ
reset กลับค่าเริ่มต้น การตั้งค่านี้เก็บใน `localStorage` ของ browser เท่านั้น ไม่ถูกส่งไป
server และไม่แชร์ข้าม browser/device

ชุดปุ่มที่เพิ่มเข้ามาสำหรับเปิดใช้เองได้รวมถึง:

- Navigation/editing: `PgUp`, `PgDn`, `Home`, `End`, `Ins`, `Del`
- Function keys: `F1`-`F12`
- Symbols: `!`, `@`, `#`, `$`, `%`, `^`, `&`, `*`, `(`, `)`, `_`, `+`, `=`, `{`, `}`, `[`, `]`, `:`, `;`, `"`, `'`, `<`, `>`, `?`, `\`
- Ctrl shortcuts: `^C`, `^Z`, `^X`, `^R`, `^F`, `^A`, `^E`, `^D`, `^L`, `^U`, `^K`, `^W`, `^P`, `^N`

modifier ทั้งสามตัวใช้สถานะเดียวกันระหว่าง quick row, ตารางปุ่ม และคีย์บอร์ดจริง
สถานะที่แตะครั้งเดียวจะถูกใช้และปลดพร้อมกันกับ input ถัดไป ส่วนสถานะล็อกจะค้างจนกด
modifier ตัวนั้นอีกครั้ง การเปิด/ปิดตาราง หมุนจอ หรือ reconnect ไม่เปลี่ยนสถานะนี้
ทุกปุ่มยังผ่าน `input-pipeline.ts` เหมือน input จากคีย์บอร์ดจริง ดังนั้น sticky
`Ctrl` / `Shift` / `Alt`, application cursor mode, และกติกา modifier เดิมยังมีผลตามเดิม

recognizer ไม่รวบสองแตะเป็นท่าของตัวเองเลย ทุกแตะเป็นคลิกที่ส่งถึง TUI ตรงๆ
เพื่อไม่ให้แย่งดับเบิลคลิกไปจากแอปข้างใน — herdr ใช้มันเลือกคำแล้วคัดลอกให้อัตโนมัติ
(ต้องแตะสองครั้งให้ห่างกันไม่เกิน 1 คอลัมน์ ซึ่งบนมือถือแปลว่าต้องเล็งนิ่งพอสมควร)

การเลื่อนถูกส่งเป็น wheel event ให้แอปข้างในตัดสินใจเอง ว่าจะเลื่อน scrollback ของมัน
หรือส่งต่อให้แอปที่ซ้อนอยู่ ตามที่แอปนั้นขอ mouse reporting ไว้หรือไม่

## เลือกและคัดลอกข้อความ

กด `⧉` แล้วลากนิ้วคลุมข้อความที่ต้องการ ปล่อยนิ้วแล้วแผ่นข้อความจะเด้งขึ้นมา จากตรงนั้น
กด **คัดลอก** ทีเดียวจบ หรือ **กดค้างบนข้อความ** เพื่อเปิดเมนูของระบบ (Copy, Share,
แปลภาษา) และเลือกเฉพาะบางส่วนซ้ำอีกชั้นก็ได้ กด `⧉` อีกครั้งเพื่อออกจากโหมด

เคล็ดลับ: **เริ่มลากจากกลาง pane ที่ต้องการ** ไม่ต้องเล็งขอบให้แม่น เพราะขอบถูกตรึงให้
อยู่แล้ว — ลากเลยขอบออกไปไกลแค่ไหนก็ได้ ปลอดภัย

**ตัด sidebar และเส้นแบ่ง pane ออกให้เอง** โดยไม่ต้องตั้งค่าอะไรเลย ทุกครั้งที่เข้าโหมด
แอปจะสแกนหาคอลัมน์ที่เป็นเส้นแนวตั้ง (`│`) แล้วตรึงกรอบเลือกให้อยู่ใน pane ที่เริ่มลาก
ลากเลยเส้นไปแค่ไหนก็ไม่มีเส้นแบ่งและไม่มีข้อความจาก pane ข้างๆ ติดมา ใช้ได้ทั้ง `herdr`,
`tmux`, `vim` ที่ split แนวตั้ง และ TUI อื่นที่แบ่งจอด้วยเส้นแนวตั้ง — เพราะมันอ่าน
"ตัวอักษรที่อยู่บนจอ" ไม่ได้คุยกับแอปข้างในเลย

ตรวจสดทุกครั้งแทนการจำค่าที่ตั้งไว้ เพราะค่าที่จำไว้จะผิดทันทีที่ย่อ/ขยาย sidebar หรือ
หมุนจอ แล้วอาการที่ได้คือ "คัดลอกมาได้ครึ่งเดียว" ซึ่งหาสาเหตุยากกว่ามาก

ข้อจำกัดที่ควรรู้:

- **Safari บน iPhone ไม่รองรับ Fullscreen API สำหรับหน้าเว็บทั่วไป** จึงซ่อนปุ่ม `⛶`
  โดยอัตโนมัติ ส่วน Chrome บน Android และ Safari บน iPad จะแสดงปุ่มเมื่อ API ใช้งานได้
- **เลือกได้เฉพาะที่อยู่บนจอ** ตอนแอปอยู่ใน alternate screen (`herdr`, `tmux`, `vim`
  อยู่ในโหมดนี้ตลอด) xterm ไม่มี scrollback — ข้อความที่เลื่อนขึ้นไปแล้วอยู่ในมือแอป
  เลื่อนกลับมาก่อนด้วยท่าปกติ แล้วค่อยกด `⧉`
- **ตรวจเจอเฉพาะเส้นที่เป็นตัวอักษร** — เส้นตรง (`│ ┃ ║ ▏ ▕ ▌ ▐ | ┆ ┊ ╎ ╏`) ตัวเชื่อม
  (`┬ ┴ ┼ ├ ┤` และชุดเส้นหนา/เส้นคู่) และมุมกล่อง ส่วน pane ที่แบ่งด้วยสีพื้นหลังล้วน
  โดยไม่มีอักขระเลย จะตรวจไม่เจอ
- **บน iPad ไฮไลต์ที่เห็นจะเป็นทรงเชิงเส้น** ไม่ใช่ทรงบล็อก (ข้อจำกัดของ xterm บน
  platform ที่รายงานตัวเป็น Mac) แต่**ข้อความที่คัดลอกได้ยังถูกตัดคอลัมน์ถูกต้อง**
  เพราะเราดึงข้อความเองไม่ได้ใช้ของ xterm
- **คีย์บอร์ดบนจอกับโหมดเลือกอยู่ด้วยกันไม่ได้** เข้าโหมดแล้วคีย์บอร์ดจะถูกปิดให้
  และกด `⌨` ระหว่างเลือกจะออกจากโหมดก่อน — เพราะคีย์บอร์ดที่โผล่มาระหว่างลากจะหด
  viewport ทำให้กรอบที่เลือกวิ่งหนีมือ
- **`⎘` ต้องขออนุญาตอ่านคลิปบอร์ด** Chrome บน Android ถามครั้งแรก Safari บน iOS
  ถามทุกครั้ง ถ้าปฏิเสธจะมีข้อความบอกให้ใช้ปุ่มวางของคีย์บอร์ดแทน

## สิ่งที่ต้องรู้

- **proxy นี้ไม่ทำ persistence ให้** — ปิดเว็บหรือเน็ตหลุด = PTY ตาย งานที่ค้างหายหมด
  persistence เป็นหน้าที่ของ `SHELL_CMD` ล้วนๆ ดู [เลือก shell](#เลือก-shell-shell_cmd)
- **การตั้งค่า bottom tools เป็น local UI preference** — เก็บใน `localStorage` key
  `browser-terminal:keybar:v1`; ล้าง site data หรือกด reset ในแผง `⚙` เพื่อกลับค่าเริ่มต้น
- **ขอบ pane ที่ลากเอง** เก็บใน `localStorage` key `browser-terminal:selection:v1` เป็น
  ตัวสำรองเมื่อตรวจเส้นแบ่งอัตโนมัติไม่เจอ และถูกทิ้งทันทีที่ความกว้าง terminal เปลี่ยน
- **session เดียวเท่านั้น** เปิดที่ใหม่จะเตะที่เก่าออก (โดยตั้งใจ)
- **logout เพิกถอน session ทุกใบ** ไม่ใช่แค่เครื่องที่กด — เพราะถ้า cookie รั่ว
  การลบฝั่งเบราว์เซอร์ไม่ได้ทำให้ token ที่อยู่ในมือคนอื่นใช้ไม่ได้
- **rate limit แยกตาม IP** แต่จะได้ IP จริงก็ต่อเมื่อตั้ง `TRUST_PROXY=1` ตอนอยู่หลัง
  proxy — ยืนยันแล้วว่า `tailscale serve` ส่ง `X-Forwarded-For` มาให้จริง
- **อัปเกรด Node แล้วต้อง `pnpm rebuild`** — `node-pty` เป็น native module
  ถ้าไม่ rebuild service จะพังด้วย `NODE_MODULE_VERSION mismatch` ที่อ่านไม่รู้เรื่อง
- **`PUBLIC_ORIGIN` ต้องตรงกับที่เปิดในเบราว์เซอร์เป๊ะๆ** ถ้าไม่ตรง WebSocket จะโดน
  ปฏิเสธ 403 และถ้าใส่ `https` ทั้งที่เสิร์ฟจริงเป็น `http` เบราว์เซอร์จะทิ้ง cookie
  เงียบๆ อาการคือล็อกอินสำเร็จแล้ววนกลับหน้า login
- **`focus` ไม่ใช่ตัวชี้วัดว่าคีย์บอร์ดบนจอเปิดอยู่** — Android ซ่อนคีย์บอร์ดโดยไม่ blur
  ใช้ `keyboard-visibility.ts` ที่วัดจาก `visualViewport` เท่านั้น
- **physical keyboard ต้องไม่เสีย focus ตอน Android หด IME** — input จาก Bluetooth
  keyboard อาจตามด้วย `visualViewport` ที่เปลี่ยนจากเห็น → ซ่อนเหมือนกับปุ่มซ่อน
  คีย์บอร์ดของ Android แต่กรณีแรกต้องคง helper textarea ของ xterm ไว้ ส่วนกรณีหลัง
  ยังต้องปล่อย focus ตัวชี้วัดที่เชื่อถือได้คือ `onData` ซึ่งแปลว่า xterm รับ input
  แล้ว ไม่ใช่ชนิดของ DOM keyboard event หรือสถานะ viewport ณ ตอนนั้น ดู one-shot
  correlation ใน `keyboard-visibility.ts`
- **การลากต้องตั้ง `buttons: 1` บน `mousemove` ด้วย ไม่ใช่แค่ `mousedown`** — xterm
  แยก "ลากทั้งที่กดปุ่มอยู่" ออกจาก "เลื่อนเมาส์เฉยๆ" ด้วยฟิลด์นี้ล้วนๆ และ listener
  ของการลากอยู่ที่ `document` ไม่ใช่ที่ `term.element`
- **ห้ามใช้ `@xterm/addon-attach`** — มันข้าม `input-pipeline.ts` ทั้งก้อน
  ใช้เมื่อไหร่แถวปุ่มมือถือพังทันที
- **ห้ามเพิ่ม `addon-canvas` / `addon-webgl`** — DOM renderer คือเหตุผลเดียวที่ทั้ง
  ไฮไลต์ทรงบล็อกและการกดค้างเลือกข้อความบนแผ่นผลลัพธ์ทำงานได้
- **`macOptionClickForcesSelection: true` ห้ามเอาออก** — `navigator.platform` ของ
  iPad คือ `MacIntel` ทำให้ xterm คิดว่าเป็น Mac แล้วเงื่อนไข `shouldForceSelection`
  กลายเป็น `altKey && ตัวเลือกนี้` ถ้าเป็น false เงื่อนไขจะเป็นจริงไม่ได้เลย และ
  mousedown สังเคราะห์ของโหมดเลือกจะทะลุไปเป็นคลิกจริงในแอปข้างใน
- **mouse event สังเคราะห์ที่ขับ selection ต้องมี `detail: 1`** — `SelectionService`
  ของ xterm แยกทางด้วยจำนวนคลิก (`1===e.detail ? _handleSingleClick : …`) และ
  `new MouseEvent()` ที่ไม่ระบุ `detail` ได้ 0 ซึ่งไม่เข้าสาขาไหนเลย ผลคือไม่มีการเลือก
  ไม่มีไฮไลต์ และ**ไม่มี error ให้เห็น** ทั้งที่ event ถูกส่งถึงและผ่านด่านอื่นครบแล้ว
  ทุกฟิลด์อยู่ใน `selectionMouseInit()` ที่เดียว อย่ากระจายกลับออกไป
- **xterm โฟกัส textarea ทุกครั้งที่ selection เปลี่ยน บนเครื่องที่ `navigator.platform`
  เป็น Linux — ซึ่งรวม Android** (`"Linux armv8l"`) มันไว้รองรับ primary selection ของ
  X11: `refresh(true)` ยิง `onLinuxMouseSelection` แล้ว `Terminal` ตอบด้วย
  `textarea.focus()` และ `refresh(true)` ถูกเรียกใน `_handleMouseMove` ด้วย แปลว่า
  โฟกัสกลับมาใหม่**ทุกครั้งที่นิ้วขยับ** — `blur()` ตอนเริ่มลากเอาไม่อยู่ ต้องกันที่ตัว
  `focus` เอง (ดู listener ใน `initTerminal`)
- **โหมดเลือกต้องหยุด momentum ของ recognizer ตอนเข้าโหมด** — มันดักนิ้วไว้ก่อนถึง
  recognizer จึงไม่มีใครเรียก `onTouchStart` ซึ่งเป็นที่เดียวที่หยุด momentum ถ้าไม่หยุด
  การสะบัดเลื่อนก่อนกด `⧉` จะไหลต่อและยิง wheel ใส่แอปข้างในระหว่างที่กำลังลากเลือก
- **ปุ่มที่เพิ่มใหม่ในแค็ตตาล็อกต้องแทรกตาม `defaultOrder` ไม่ใช่ต่อท้าย** —
  `normalizeKeybarPreferences` ทำให้แล้ว ถ้าต่อท้ายเฉยๆ ปุ่มใหม่จะไปอยู่หลัง F1-F12
  ทั้งหมด คือลึกจนผู้ใช้เดิม (ที่มีลำดับบันทึกไว้แล้ว) ไม่มีวันเจอ

### ท่อขาออกจาก PTY

output จาก PTY ไม่ได้ยิงเข้า `ws.send()` ตรงๆ แต่ผ่าน `server/outbound.ts` ซึ่งทำสามอย่าง:

- **รวม chunk แบบ immediate-first** — chunk แรกหลังจอเงียบส่งทันที (นั่นคือ echo ของ
  ตัวอักษรที่เพิ่งพิมพ์ หน่วงไม่ได้) chunk ที่ตามมาใน 5 ms ถึงจะถูกสะสมแล้วส่งรวดเดียว
  burst จาก `cat` หรือ build log จึงถูกยุบเหลือ ~200 frame/วินาที แทนที่จะเป็นพันเฟรม
- **หยุดอ่าน PTY เมื่อคิวยาวเกิน** — เกิน 32 KB สั่ง `term.pause()` และ resume เมื่อ
  ระบายต่ำกว่า 8 KB นับจาก callback ของ `ws.send()` ไม่ใช่ poll ถ้าไม่ทำ ข้อมูลที่
  ค้างในคิวจะดองตัวอักษรที่ผู้ใช้พิมพ์ตามหลังไว้เป็นวินาที (head-of-line blocking)
  ซึ่งเป็นอาการที่รู้สึกได้ชัดที่สุดบนมือถือ — ตัวเลข 32 KB นี้นับไบต์**ก่อนบีบอัด**
  (`outstanding` บวกกับไบต์ที่สะสมรอ flush) จึงเป็นเพดานแบบ conservative คิวจริง
  บนสายเล็กกว่านี้ตามอัตราการบีบของ deflate (มักบีบได้ 5-10 เท่ากับข้อความเทอร์มินัล)
- **บีบอัดเฉพาะ frame ใหญ่** — `perMessageDeflate` มี `threshold: 1024` เพื่อไม่ให้
  frame echo จิ๋วๆ ต้องเสียเวลา deflate

ทั้งสามอย่างนี้ลด**สิ่งที่ทำให้แย่กว่า RTT** ไม่ได้ลด RTT เอง — บนเส้นทางมือถือ cellular
ผ่าน Tailscale RTT อยู่ที่ 60-250 ms และเป็นเพดานที่ transport ลดไม่ได้
